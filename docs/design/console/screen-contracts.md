# Per-screen implementation contracts

These24 screen-purpose records reconcile the full-menu studies with the latest approved navigation, approval and investigation amendments. [screen-inventory.json](screen-inventory.json) carries machine-readable routes, topology/access variants and boundaries. Hash routes are prototype references, not an imposed production router/API. Synthetic IDs below demonstrate exact relationships only in the explicitly selected synthetic dataset.

All screens inherit [design-and-navigation.md](design-and-navigation.md), including eight distinct read states, protected direct-link denial, final-render focus, scope-preserving Back, no first-record fallback, no implicit operational action and no fake missing values. Every interactive control needs an actual authorized handler or a clearly specified deferred state; a disabled prototype button is not a completed feature.

### Review acceptance details

Current synthetic request02 proposes `wf-demo-01 /1.0.7`; request01 and03 have explicit `1.0.0` references but no loaded exact definition. These are authored safety examples, not recovered backend or golden mappings. The wire operation is structured MCP approve with `Approved` or `Rejected`, not an agent prompt. The browser's reason requirement is an approved UX rule even though the inspected wire schema calls reason optional; define authoritative validation without assuming it exists today.

A successful response alone does not settle a decision. Resolve from authoritative current state; a timeout with unknown commit result requires a read, not automatic replay. Two opposing decisions must not both be accepted. Preserve accepted attribution and reason; do not trust locally rendered actor text. Reviewed-content binding, expiry and conditional decision safety are prerequisite contracts, not client-side-only checks.

The existing approval detail DTO lacks several ledger/repeat/provenance fields. Do not synthesize target namespace, source cluster, initiator, original parameters or history from display names, current catalog state, another RR or the current chat. The source matrix names the required adapter/read-contract work. Reuse the minimum reviewer boundary rather than granting global audit/SRE rights.

## Materially different states to preserve

| Area | State dimensions / required destinations |
| --- | --- |
| All reads | Loading; ready; valid empty; partial/truncated; stale; unavailable; forbidden; missing/out-of-scope ID/filter. Preserve observation/provenance and bounded retries. |
| RAR | Pending; submitting; accepted decision; expired; decided elsewhere/conflict; unreadable/missing; no permission; ambiguous write; related evidence unavailable/partial/stale/empty/forbidden independent of eligibility. |
| Chat rendering | Plain/Markdown fallback, no RCA, RCA without data, early RCA before workflow discovery, discovery pending, complete empty/no-match, many/no recommended/ruled-out options, existing findings retained after response interruption. These remain source-parity obligations, not claimed fully covered by six stage examples. |
| Workflow actions | Countdown/cancel/execute-now; alternate confirmation; already-actioned/phase/ownership guards; dismiss/escalation/no-options reason/error; recovery/alignment/target-divergence cases from existing source. Approve/reject RAR remains outside chat. |
| Session/transport | Idle, active tool/AI response, backgrounded presenter, source/auth invalidation, response interrupted/failed/timed out, disconnected RR observation, stale/late events, explicit terminal state, new conversation and owner-scoped history/draft restore. No auto replay. |
| Verification | All actual step names/status/details/retries, not-reported versus failed, empty/partial results, missing/invalid/zero clocks, completed lifecycle without duration, non-null partial score and separately reported recovery. |

Each production screen's implementation/test manifest must identify these states, source fields, guards, permission scope, timestamps, return targets and unsupported gaps. Do not mark a whole screen implemented merely because its happy-path screenshot matches.
